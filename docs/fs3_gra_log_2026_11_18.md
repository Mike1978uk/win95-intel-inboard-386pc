# FS3 `CUSTOM.GRA` interface log, 2026-11-18 (X30 step 1)

Logging driver `tools/fs3gra/` (tail on the owner's PS21.GRA; the built file holds Microsoft code and stays
out of the repo). Bed `vm_6695_w2` (486, Graphics Ultra VGA, X22 build), FS3 3.00 started with `FS3 X`,
menu 1 / N (Custom Drive) / C (demo, no sound) / B / N, about 2 minutes of the demo. Log read from bed
memory with `tools/bed_mem.py`; decoded by `tools/fs3gra/decode.py` (`captures/2026-11-18_fs3log_bed/decode.txt`).

| Finding | Value |
|---|---|
| Option N loads `CUSTOM.GRA` and runs it | yes: the demo flies with PS21's picture (screens in the capture folder, not committed) |
| Per frame (3,518 frames) | 35.7 polygons (max 45), 166.7 vertices (4.7 a polygon), 12.3 lines, 1.1 text calls, 1.5 row fills |
| Polygons by corners | 3: 22%, 4: 43%, 5: 19%, 6-8: 12%; 9-31+: 4% (16 corners: 2,486; 31 or more: 412) |

| Unused in flight | 486h horizon (19), 492h, 4B2h, 4BAh, 4BEh; 48Eh mode never called after init (mode set inside init) |
| Present (47Eh) | once a frame; 496h (draw into the RAM buffer) about once a frame |

2,000 port writes a frame, ~15-20 ms at 7.6 us plus FIFO polling, so the 3D window could run at 30+ fps
before the panel. Needs: `m8dos` MAXV raised from 16 to 32 or more (polygons up to 31+ corners seen), and
