# Mach8 driver retro, end of 2026-10-22: ours, ATIM8 and XFree86

The real 5160, 800x600x8, LEAN boot for both drivers, one bench after `M8IDLE`; pixels = ATIM8's in all 35
tests in every run. Card log: `docs/captures/2026-10-22_card/`. **Overall 1.274x ATIM8** (1.062x at the start
of the day). XFree86 3.3.6's Mach8 server (`references/xfree86_336_mach8/`, Kevin E. Martin) is the other
working driver for this chip; its column is from its source, not measured here.

## What the day taught

- The card's time is port writes, engine waits and per-call overhead, not compiled C (`-ox` neutral). Count
  writes per operation; drop waits that nothing depends on; set up once per call.
- Every lever that paid came from reading ATIM8 or the guide, then a cheap card probe (`tools/m8probe/`).
  Undocumented bits are not always levers: PATT_LENGTH 8/13/14 and LINEDRAW_OPT bit 3 do nothing.
- A test that bundles changes can hide a gain: no-idle-waits measured neutral on 10-21 with host transfers
  mixed in, and 1.10-1.21x on text and lines alone.
- After every win, ask where else on the card it carries (owner).
- The bed is a pixel check with known gaps: SCAN_TO_X ignores PATT_INDEX there; engine time is instant.

## Aims

1. Equal or better than ATIM8 in every test: the per-call path first (it moves most of the table), then
   stretch, uploads, colour brushes.
2. Less bus and CPU time per call even where ahead: it frees the bus for the XT-CF, sound, network and SCSI.
3. Then the experimental side, on a driver that is already faster: DirectDraw (page flip, line counter),
   more apparent colours, vectors and 3D on the 2D engine (`docs/mach8_unused_silicon_audit.md`,
   `docs/atim8_port_census.md`).
