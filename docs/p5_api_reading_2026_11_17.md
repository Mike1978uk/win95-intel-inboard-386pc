Allegro titles at 8 bpp on an 8-bit ISA bus are the realistic users. |

## 3. BRender

Corrections to earlier notes: **(a)** the 1997 tree's `ati/` folder is ATI's **Rage 3D CIF back end for Windows** (device name `"RAGE_WIN"`), not an unexplained folder; **(b)** `v1.1.2` has no loadable driver split at all (built-in z-buffer rasteriser); the `.BDD` plug-in design appears in the 1996-97 tree.

| | |
|---|---|
| Gave | **Driver entry point**: `BrDevAdd()` loads the named image with `BrImageReference`, then looks up the export `"BrDrv1Begin"` and calls it: https://github.com/foone/BRender-1997/blob/master/fw/devlist.c (line 129). The soft renderer's version in `softrend/driver.c` returns a `br_device`; `ati/Driver.c` exports `BrDrv1ATIBegin` for `"RAGE_WIN"`. |
| | **Two-level split** in `softrend/`: `rendfcty.c` (`RendererFacilitySoftAllocate`, `rendererNew`) asks `BrPrimitiveLibraryFind` for a **primitive library**, a second driver image `pentprim/driver.c` (device `"SOFTPRMF"`, library `"Default-Primitives-Float"`), https://github.com/foone/BRender-1997/tree/master/pentprim . A DOS `.BDD` is therefore at minimum (renderer, primitives, output) and the 1997 `3dfx/` folder ships `glide/` and `davesdrv/` beside the device code. |
| | **Primitive table**: `pentprim/Prim_*.c` define arrays of `brp_block`: a render-function pointer, a text name ("Indexed, Z Buffered, Interpolated Intensity, Textured"), primitive type (`BRT_LINE`, `BRT_POINT`, `BRT_TRIANGLE`), per-vertex component mask (`CM_SX|CM_SY|CM_SZ|CM_I|...`) and slot map. Components are in `softrend/priminfo.h` (`C_SX,C_SY,C_SZ,C_U,C_V,C_I,C_R,C_G,C_B`, `NUM_COMPONENTS 16`); flags include `BR_PRIMF_SCISSOR`, `BR_PRIMF_BLENDED`. The renderer picks the block whose masks match the model's material: https://github.com/foone/BRender-1997/blob/master/softrend/priminfo.h |
| | **Routine families generated from lists**: `pentprim/prim_t8.ifg` is processed by `infogen.pl` into names like `TriangleRender_ZPTIFB_I8_D16_256_FLAT` (flags: z_buffered, triangle, index8, interpolated/constant intensity, texture size, perspective, fog, blend). The untextured flat/Gouraud lists are in the smaller `prim_p8.ifg` (745 bytes, not read; exact names nv). Per-triangle float setup: `pentprim/Fpsetup.asm` (`SETUP_FLOAT_PARAM`: parameter deltas, x/y gradients from two edge vectors, a few cycles per parameter). |
| | **Where flat spans come from in 1.1.2**: `ZB/TRIGEN.C` `GenericTriangleRender(v0,v1,v2)`: sort vertices in Y, compute `zb.top`, `zb.bot` and long `zb.main` edges, gradient divisor, then `zb.trapezoid_render(&zb.top)` and `(&zb.bot)`. `GenericTrapezoidRender` walks rows and calls a **per-pixel callback** `zb.pixel_render(x, y)` (types `br_trapezoid_render_cb` and `br_pixel_render_cb` in `ZB/ZB.H` lines 208-216). Specialised flat/Gouraud scan loops live in assembler (`ZB/TI8_PIZ.ASM`, `PSCAN.ASM`, `INNERA.H`). https://github.com/foone/BRender-v1.1.2/tree/master/ZB |
| | **ATI hardware route**: `ati/Rendfunc.c` has `ATI_LS_TriRender`, `ATI_LF_TriRender`, ... which fill `C3D_VTCF` vertices and call `ATI3DCIF_RenderPrimList` in batches (`FlushPrimitivesATI`), switching 2D/3D state with `ATI3DCIF_RenderBegin/RenderEnd` (`SetRAGE3DHardware`/`SetRAGE2DHardware`). That is an existing example of a BRender back end delegating *whole triangles* to a chip. |
| | **Device names seen on DOS**: `mcga.bdd`, `3DFX_DOS.BDD`, `RAGE_DOS`; a renamed `mcga.bdd` ran (snippet, from the earlier doc: https://www.vogons.org/viewtopic.php?p=310432 ). |
| Did not give | The **DOS `.BDD` image format** (what linker, DPMI or LE; `BrImageReference` hides it in `fw/`, not read). Any shipping DOS title's driver source. `RAGE_DOS` is named in a forum list; no source for it in the repo (the `ati/` code is the Windows build; a `DOS_BUILD` ifdef exists in `Ati3dcif.h`). Whether `v1.1.2` makefiles build a DOS `.BDD`: not found. The licence is MIT for both trees (per the repos' `LICENSE`, listed, not read). |
| Lesson for our engine | **1. Cut at the trapezoid**, not the pixel: the flat-colour case needs only the three edge slopes and two heights, not a callback per pixel. **2. Select routine by property mask** (flat / Gouraud / textured / Z) and give the unsupported ones a fallback to the existing software path; that is the same decision our HAL makes between "flat patch" and "joined patch". **3. Batch vertices**: `FlushPrimitivesATI` collects up to `MAX_VERTEX_STORAGE` vertices and submits once. **4. Component masks** tell the driver what crosses the bus: a flat triangle needs `SX,SY` and one colour, 3 x 2 coordinates, no Z, no UV. |
| File-swap verdict | **Best of the set**: a swap was shown, the driver contract (`BrDrv1Begin`, device, output facility, renderer facility, primitive library) is public and MIT, and titles run (Carmageddon-class, 3D Movie Maker; BRender 1.3.2 in dethrace-labs/BRender-CrocDE was not read). Costs: a `.BDD` replacing `mcga.bdd` must also provide an output facility that blits our back page (our CRT_OFFSET flip), and software-rendered titles are textured, so flat-only fidelity is low. |
| Next step | Read `fw/loader.c` and `fw/image.c` (not fetched) for the image format; read `softrend/onscreen.c`/`renderer.c` for the call order; read `pentprim/prim_p8.ifg` for the flat/Gouraud names. Optionally a one-file clone under `C:\Users\lycet\Downloads\p5_src\BRender-1997`. |

## 5. IBM 8514/A Adapter Interface (AI)

| | |
|---|---|
| Gave | **Detection and calling**: INT 7Fh with AX=0105h returns CX:DX pointing at a table of far pointers, one per function number; most functions take a pointer to a parameter block whose first WORD is its byte count (https://pdos.csail.mit.edu/6.1810/2017/readings/hardware/vgadoc/AI.TXT , VGADOC, read; Ralf Brown: https://mirror.cs.msu.ru/oldlinux.org/Linux.old/docs/interrupts/int-html/rb-8003.htm snippet). Function numbers (VGADOC, to 50h): drawing `HLINE 00`, `HCLINE 01`, `HSCP 04`, `HBAR 05` / `HEAR 06` (area begin/end, **the polygon-fill pair**, may not nest), `HSCOL 07`, `HOPEN 08`, `HSMX 09`, `HSBCOL 0A`, `HEGS 0D`, `HSHS 14` (scissor), `HBBW 15` / `HCBBW 16` (BitBlt write host data), `HBBR 17`, `HBBCHN 18`, `HBBC 19` (copy), `HSMODE 1C`, `HRECT 20`, `HCLOSE 22`, `HSPATT 12`, `HMRK 32`, `HPEL 40`, `HSBMAP 45`, `HBMC 47`, `HSDW 48`, `HSPRITE 49`, `HRWVEC 4B`, `HQDEVICE 50`; text `HCHST 26`; `HINT 10` (wait for idle or vblank). The IBM technical reference in the repo has the same set with full descriptions: `references/8514a_docs/ibm_8514a_techref_198704.txt` (TOC lines 117-200); book copy `references/8514a_docs/richter_smith_graphics_programming_8514a.txt`. |
| | **ATI's loader**: `HDILOAD` is the "Turbo AI" for Mach8/Mach32, "100% compatible with AI programs written for the IBM 8514/A" (our own read of ATI `hdload\README` in `docs/ati_readme_findings_2026_10_23.md`); ATI `README.ATI` says 8514/A software "will require" `\HDIPCDOS\HDILOAD.EXE`. |
| Did not give | **Programs that use it**: VGADOC names none (it lists implementations: 8514/A, XGA, Image Adapter/A, ATI Mach, Tseng RIXAI). ## 6. Others, one paragraph each

**S3 S3D Toolkit.** https://github.com/kytulendu/S3DTK holds SDK 2.6 (`H/S3DTK.H`, `LIB`, `DRIVERS`, `SAMPLES`, `S3DTK.HLP`). The header defines a **function-list struct** returned by `S3DTK_CreateRenderer`: `SetState`/`GetState`, `TriangleSet(pFuncStruct, pVertexSet, NumVertices, SetType)` with `S3DTK_TRILIST/TRISTRIP/TRIFAN/LINE/POINT`, `TriangleSetEx` (state pairs per call), `BitBlt`, `BitBltTransparent`, `RectFill`, `StretchDisplaySurface`. Vertices: lit `X,Y,Z,W,B,G,R,A` and textured plus `D,U,V`. Teaches: indexed vertex arrays and strips/fans cut the bytes per triangle by 2-3x on a slow bus; a **dispatch struct per renderer instance** is the shape a replaceable driver takes. Did not give: DOS delivery (header says DLL-style `DllExport`; DOS use is claimed only in a Vogons snippet, https://www.vogons.org/viewtopic.php?p=1254615), triangle setup maths.

**ATI 3D Rage CIF.** The complete header is in the BRender-1997 tree: https://github.com/foone/BRender-1997/blob/master/ati/Ati3dcif.h (marked "Trade secret of ATI ... unpublished"; read it, do not copy into our tree). Entry points: `ATI3DCIF_Init`, `ContextCreate`, `ContextSetState`, `RenderBegin`, `RenderPrimList`/`RenderPrimStrip`, `TextureReg`, `LoadObject` (bus-master load), and `ATI3DCIF_DosInit(PVOID pPHXINFO)` under `DOS_BUILD`. Primitives `C3D_EPRIM_LINE, TRI, QUAD, RECT, POINT`; vertex types `VF, VCF, VTF, VTCF` (float). Shade modes include solid/flat colour (`C3D_ERS_SOLID_CLR`), Z modes, a **screen-aligned rect primitive** (`C3D_CAPS1_RECT`). Restriction 5: coordinates pre-clipped to -2048..2047 / -4096..4095. Teaches: how a chip vendor expresses *flat colour as a state* (`ERS_SOLID_CLR`, `ERS_SHADE_MODE`), plus a rect primitive in a 3D API, which is our fill. Did not give: register traffic, any DOS game that calls `DosInit`.

**Rendition Speedy3D.** https://sourceforge.net/projects/dosbox-rendition/ (fork of DOSBox, "Speedy3D graphics wrapper passthrough", runs titles with the closed RReady driver or an open equivalent). The page does not say what calls are hooked or whether the API is span- or triangle-based (the plan's "span-based" is nv); code browser: https://sourceforge.net/p/dosbox-rendition/code/ (not read). Teaches only that a DOS 3D API can be intercepted at the call boundary, same as Glide. Next: read its source for the hook list.

**PowerVR SGL.** Imagination released the Series 1 sources and docs under MIT: https://github.com/powervr-graphics/PowerVR-Series1 (articles: https://www.cnx-software.com/2022/03/24/imagination-open-sources-powervr-series-1-gpu-drivers/ ). `Documentation/sgl/` has `Docs`, `Drivers`, `Examples`, `Intro`, `QuickStart`, `Tools`, `Tricks` and an SGL reference plus `Perform.htm` ("Performance Notes", marked NDA). The HTML pages fetched were frames with no body text, so the **scene-at-once sort** claim is nv; the real text sits in files not opened. Code is "only provided as a reference". Teaches (nv until read): the API hands the whole scene to the chip, which sorts per tile instead of using Z: the model closest to our depth sort. Next: open the `Intro` and `Tricks` content files.

**Matrox MSI.** https://en.wikipedia.org/wiki/Matrox_Simple_Interface : proprietary DOS and Windows 95 API for the Mystique, max 640x480x16, z-buffer, no bilinear; dropped after the m3D card. No header, DLL or title list beyond MechWarrior 2 (Mystique edition). Teaches nothing recoverable; park.

## Recommendation

1. **BRender first** (engine and swap): MIT source, a published driver contract (`BrDrv1Begin`, primitive blocks with component masks), a trapezoid cut already in 1.1.2, a flat/Gouraud 8-bit path, and a rename that already ran. Read `fw/image` and `prim_p8.ifg` next, then clone one tree.
2. **VBE/AF second** (swap): the only file-swap with a documented signature and a trivial one-file install; its table (`DrawTrap`, `DrawScanList`, `DrawTri`, `PutMonoImage`, `SetVisibleBuffer`) is our engine's own vocabulary. Needs a Mach8 driver written from the stub.
3. **Glide 2.x third** (shape and a verified swap point): public source and manual, OVL replacement proven by Glidos/dgVoodoo/DOSBox-X; the OVL ABI is unread and titles want Z and Gouraud.
4. **ATI CIF header and S3D Toolkit as design models** (both are in public trees); AI/HDILOAD as a pixels test bed; CGL, Speedy3D, SGL, MSI after disassembly or source reads.
5. First implementation target is not an API: it is an internal `DrawTrap`/`DrawScanList` primitive, which every API above reduces to.
